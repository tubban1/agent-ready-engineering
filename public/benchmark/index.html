01 / SELF ASSESSMENT

提交 MCP · 即时静态预检

仅接受真实可连接的公网 HTTPS MCP Endpoint。自动执行 initialize / tools/list 并生成可追溯的静态预检；不接受 GitHub 仓库、本地 stdio 或手工 Manifest 作为评分目标。

无需上传源码或工具清单。需要能在无需登录的状态下完成 MCP 协议初始化和工具发现；需要 OAuth 的服务暂不能自动评分。GitHub 只用于后续补充源码证据，不是评分入口。

如何让 ChatGPT / Claude 对自己的 MCP 进行 ARE 自评？

先在 Agent 中连接 ARE MCP：https://are.world2.co/mcp，并确认工具列表中有 are_score_mcp。随后调用该工具，只传入 endpoint 参数。单凭提示词不会自动连接 MCP。无法配置连接时，可直接通过本页提交 HTTPS Endpoint。

直接用浏览器打开 /mcp 出现 HTTP 406 不等于 MCP 服务故障，必须由支持 MCP 协议的客户端访问。

证据分级： 只以实际连接 Endpoint 返回的 tools/list 做静态预评估。源码分析、真实任务和 39 项成熟度验证必须另行提供证据；工具清单不会被原文存入数据库。

04 / VALUE & METHODOLOGY
为什么需要 ARE Benchmark
先证明工程建议对 Creator 有价值，再开展大规模排名。


P0 · 价值判断
先识别 Creator 的真实任务：过审准备、Agent 成功率、成本和信任。记录修改前基线；未经测试的收益只是可验证假设。
证据分级
目录元数据、Manifest、自述、源码、真实 Agent 任务和独立复核具有不同可信度。缺失信息保持未知，不自动判为失败。
P8 · 效果回顾
保留版本、整改记录和再测试，重点测量已确认问题、有效修复、实际任务效果、Creator 后续参与。


本页不是 OpenAI / Anthropic 官方审核服务，不承诺通过审核。匿名预检不调用外部工具的业务动作；授权运行、故障注入、L0–L4 成熟度验证需要独立测试与证据。未经 Creator 授权不把匿名提交当作正式公开认可。
