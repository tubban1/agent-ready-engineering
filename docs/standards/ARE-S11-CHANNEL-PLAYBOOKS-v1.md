# ARE S11 — Four Channel Release Playbooks v1

Date: 2026-11-16. Owner: ARE / World2. Language: English canonical; Chinese for ModelScope. Source: S0–S13 case evidence, the ARE publication runner, and verified permissions.

This is a version-controlled procedure. A GitHub or ARE-hosted copy is **NOT** evidence of publication on Hugging Face, ModelScope, X, LinkedIn or Reddit.

## Shared gate and release evidence

For every qualified MCP case: inspect the 39 check IDs, tool contract vs execution coverage, real Agent + independent Oracle, source-to-production mapping, and safe public disclosure. Build reusable assets using scripts/are_s11_build.py, scripts/are_s11_media.py and scripts/are_s11_video.swift. Do not reclassify NOT_VERIFIED as PASS or single-run success as a measured reliability rate.

Canonical Solarstorm deliverables: https://are.world2.co/evidence/solarstorm/ (interactive evidence) and https://are.world2.co/datasets/solarstorm-20261116/ (dated JSONL). The demo does NOT perform live MCP calls and does not confer any certification. All external releases should link to these verified sources.

For each channel save: project ID, assessment run, channel, publisher identity, exact content hash, media files, authorization, draft/submitted/published/moderated state, real URL, publish timestamp, provider or independent browser readback, follow-up Calendar task. The project-wide CLI scripts/are_publication.py validates actual permalink receipts and prevents duplicate channel success.

2. Use an authenticated publisher whose identity suits ARE / Tubban. Create an actual public HF Dataset repo; upload all files and read back the live repo and Dataset Viewer. A generated local folder alone is CONTENT_READY.
3. Create one Static Space with dist/solarstorm-s11-v1/hf-space/index.html and README.md (sdk: static). After publishing, test public URL, filters, bilingual toggle, all 39 rows and Copy Prompt. No paid inference or unauthorized arbitrary third-party MCP calls.
4. Publish the research article only if community moderator rules permit. A prior ARE HF forum post was hidden pending review: do not duplicate or evade moderation.
5. Record separately HF_DATASET, HF_SPACE, HF_COMMUNITY publication URLs and revisions. File any real public comments for weekly review.

Pilot: signed-in HF account wihaha with Tubban organization visible; no local HF API token or write-capable HF plugin. Browser Create Dataset was rejected as CURSOR_ACTION_REQUIRES_HUMAN. Thus external HF repo and Space are PENDING_HUMAN, not published. Our hosted evidence explorer is publicly available separately once production deployment passes.

## P1 — X and LinkedIn

Audience: technical partners and potential evaluators. Content: factual evidence cards, small X thread, LinkedIn engineering discussion, clearly labeled 15-second animated data-card MP4.

1. Confirm ARE-appropriate identity. Do not publish using unrelated drone/Bloomroom social brand.
2. Build 5 SVG/PNG fact-locked cards in landscape and vertical and a 15-second vertical MP4. Each numeric claim must match case manifest and dated evidence. No simulated Agent footage presented as real.
3. Prepare channel-native text from docs/channels/x/SOLARSTORM_THREAD_EN.md and docs/channels/linkedin/SOLARSTORM_POST_EN.md. X uses short post units; LinkedIn uses project context and technical question. No blanket automation spam.
4. After each authorized publish, read the public permalink and record a matching receipt. A filled editor or clicked button alone is not PUBLISHED.
5. Summarize actual replies and schedule platform feedback review in the **existing** ARE Calendar queue; never create one recurring automation per channel.

Pilot: X @tubban1 is signed in but publication triggers CURSOR_ACTION_REQUIRES_HUMAN. LinkedIn editor interaction had no confirmed permalink. Metricool connected only unrelated drone2master brand; don't reuse it.

## P1 — Reddit

Audience: independent engineering critiques. Candidate community: r/AI_Agents. Its live sidebar rules (verified 2026-11-16) prohibit spam and low-effort posts, place promotional project links in comments/weekly showcase, and limit self-promotion.

1. Check the current community rules and the signed-in user's identity/history before any post.
2. Start from the native long-form discussion in docs/channels/reddit/SOLARSTORM_DISCUSSION_EN.md. Explain reproducible observations and open questions, not an advertisement, and disclose ARE/World2 affiliation.
3. If the topic is mainly a project showcase, use the actual weekly Project Display thread; do not scatter the same promo across communities. Respect link placement and post ratio.
4. A Reddit post/comment only counts when an actual public permalink and moderation status are read back; deleted or held content is not PUBLISHED.
5. Collect substantive critiques, with attribution, as concrete next-evaluation suggestions and Calendar follow-ups.

Pilot: community rules and an active Project Display thread were observed. No approved public submission or authentic Reddit permalink was created; status NOT_PUBLISHED.

## Calendar and rollback

For every pending external channel add a REVIEW_PUBLICATION action to the existing private ARE — MCP Follow-ups calendar (not a new recurring Automation). Project/Action key must be unique, with safe=read_only and send=manual_approval. Central hourly scheduler handles due actions and weekly reviews. If a channel is blocked by login, UI human action or moderation, preserve draft and explicit blocker; never fabricate or duplicate a post. Only the individual platform-specific writer changes third-party state and must honor actual permission.

## Acceptance for the second MCP

- Public case and dataset rows trace to actual evidence.
- 39 IDs exactly, no score without strict maturity gates.
- HF/ModelScope separate live dataset/demo/content receipts; X/LinkedIn post and media receipts; Reddit discussion and moderation receipt.
- Safe Agent replay prompt binds exact public tools, no writes, independent Oracle and small call budget.
- Unified Calendar captures unresolved channel tasks and actual replies; no per-project watcher.
