# ARE 方法有效性验证与停止条件（2026-11-22）

## 用普通话解释
ARE 是一位**检查员**，不是项目本身。每次发现假 PASS 就补规则，只能说明检查员发现了漏洞，**不能自动证明检查员真的可靠**。

验证需要一次独立的“闭卷考试”：先冻结 ARE 的规则，再用从没用于调规则的新项目，比较多个 Agent 的裁定与独立专家的事实核验。不能在看了考题答案后边改规则边给自己打分。

## 三道关（目前状态：NOT_YET_VALIDATED）

1. **能抓假证据**：收集已经人工确认的真假案例，包含伪造用户授权、只执行注册第一步却写成功、同一条401复用47次、误用N/A等。任何重大假 PASS 被放行都属于 P0。
2. **能放行真证据**：系统不能只会拒绝。用真实授权、完整可复核的调用和合法的独立预期值，测量误拦截；也需要确认多步代理在任务完成后能够通过。
3. **换人换项目依然稳定**：冻结规则后，让至少 **3种 Agent、60个此前未使用的 MCP 项目**，按两轮测试，每轮至少覆盖公共远程、OAuth、API Key、本地 stdio 四类；两个独立审查员给出金标准，有分歧需裁决并留存原始证据。至少 **360条有效评测**。

### 建议的毕业分数（*提议，不是已达到*）

| 检查 | 通过线 |
|---|---|
| 有害的虚假 PASS（特别是用户授权/外部副作用） | 0 次（按冻住的测试集统计） |
| 已知有问题的评测被 ARE 拦下的比例 | ≥ 95% |
| 实际有效评测被 ARE 误拦的比例 | ≤ 5% |
| 同一个 Agent 同一个项目两轮结论一致 | ≥ 95% |
| 两个人类审查员原始结论一致 | ≥ 90%（争议另行裁决） |
| OAuth、API Key、公共远程、本地 stdio | 每类至少 10 个独立项目 |
| 两个独立批次（每批 ≥ 30 项目） | 0 个逃过的 P0 |
| 证据与准则版本 | 在考试开始前冻结；不允许用考题调参 |

以上是给“可在这个范围内投入使用”的门槛，并非对**所有 MCP、所有未来协议**的数学证明。0/60 个重大漏检，其总体失误率上限仍可能不可忽视；结果应同时报告置信区间、项目类别与成本。

### 遇到失败怎么办？
- **P0：** 当前验证批次停止计分；修复、加回归测试、用全新的盲测项目重新做闭卷考试。
- **P1：** 可以继续记录但不算已完成标准；例如可解释性、清理、计时或用户体验缺陷。
- **通过后：** 固定成稳定版本，进入维护阶段；新增 MCP 项目主要是扩展已覆盖的数据集，**不应每测一个都改引擎**。发现重大新类型问题时才升级规则并重新验证。

### 当前实况
- 现有 ARE 案例可用作**训练/回归样本**，尤其 Raven、Keelen、Overwing；**不能再用它们给自己的最终考试打分**。
- 这份文档只定义验收标准与计算方法；**尚未完成独立金标准的数据采集、人工双盲标注和跨 Agent 实验**。
- 运行 `node scripts/are-method-benchmark.mjs <frozen-reviewed-cases.json>` 可以得到自动计算的成绩单。没有真实冻结证据时显示 `NOT_YET_VALIDATED`，不会生成虚假的高分。
