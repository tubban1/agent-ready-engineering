# ARE Maintainer Retest — 维护者修复后自检提示词（中文）

**用途：** 对收到 ARE 报告的维护者，让其在拥有的代码仓库/测试环境核对问题并产生前后对照证据。不可将“自报修复”直接等同 ARE 独立复测通过。

## 可复制提示词

> 我是 `<SERVICE_NAME>` MCP 的授权维护者。请根据 ARE 报告 `<REPORT_URL_OR_FILE>`，在固定源码和**专用测试环境**中进行诊断与修复后复测。历史评估版本 `<BASELINE_COMMIT_OR_DEPLOYMENT>`；拟复测版本 `<NEW_COMMIT_OR_DEPLOYMENT>`；允许的修改范围 `<AUTHORIZED_SCOPE>`。
>
> - 先逐条解析 ARE 报告：已确认功能缺陷、独立问题、工程优化建议、证据不足、仅统计异常必须分开。报告中来源/部署绑定 UNKNOWN 的结论不可当作生产代码 Bug。
> - 对每一条明确问题，在不改动旧测试输入和 Oracle 的情况下先尝试最小化复现，并记录复现与否。不能为了修复而放宽断言、忽略返回错误、删除安全限制或覆盖旧证据。
> - 使用真实工具结果 + 独立业务状态验证修复前后行为，包含必要的负面输入及权限边界；有写入操作只能用于已授权合成资源。
> - 同时回归已正常的协议能力、工具定义、旧版客户端和相关 Agent 任务。记录模型、客户端、Schema hash、Commit、线上版本、时间、Token（如果实际可测）、P50/P95（有足够样本时）。
> - 39 项 ARE 检查仅对确有新证据的项目更新，未验证项保留；不以自评代替官方 MCP 全项合规或 ARE 独立认证。
> - 输出 `before_after.md`、`reproduction.md`、`regression.md` 和脱敏证据清单，明确 `FIX_VERIFIED / NOT_REPRODUCED / STILL_FAILS / NOT_TESTED`；如需要向 ARE 回复，只提交公开安全的复现与版本信息。
> - **未经我针对修改/发布的单独授权，不自动合并、部署、修改线上账户或公开安全细节。**
>
> 最后给出三部分：改动/观察、真实复测结果、需要 ARE 独立再次验证的事项。

收到维护者复测数据后，ARE 应以**自己的 Agent/工具**在合法环境中再次复测，发布原报告的修订版本和时间戳，而非静默覆盖历史报告。
