# ARE Independent MCP Evaluation — 第三方公开评估提示词（中文）

**用途：** 社交媒体、社区和独立技术人员可复测公开 MCP 的行为。**公共第三方测试不拥有运营者的源码内网、私有凭据和生产故障注入权。**

## 可复制提示词

> 请作为一个与 MCP 运营方无关的 Agent，对公开服务 `<PUBLIC_HTTPS_MCP_URL>` 进行**有限的、合法且明确只读**的 ARE 第三方评估。
>
> 可选公开源码：`<PUBLIC_GITHUB_URL>`；ARE 规则：`https://are.fde.fan/mcp`。
>
> 1. 只通过公共 HTTPS 接入；严守服务的访问条款、机器人限制和合理限速。未授权时不能使用别人的账号、伪造令牌、绕过认证或做拒绝服务/故障注入。
> 2. 使用适用的 MCP 版本完成连接与完整分页 tools/list、资源/提示词发现；逐工具记录 Schema、描述、权限注解（注解不能证明真的只读）、输出与错误契约。
> 3. 对**已确认无副作用**且公开的数据检索工具，适量进行真实调用；对写入、账单、对外发送、删除、设备控制、敏感数据工具仅做静态元数据评估，标 NOT_TESTED。拒绝自动跑所谓“所有工具”高影响路径。
> 4. 如源码公开，以固定 SHA 做源码级观察；不能证明 GitHub 与线上部署映射时标 UNBOUND，不能把历史源码当现网事实。
> 5. 若能访问真实 MCP Agent Host，选择一个无副作用用户任务，用真实模型工具调用和**独立公共真值**（不是模型声明）判断业务结果；不能进行则写 NOT_VERIFIED。
> 6. 输出适用的官方 MCP 协议情况，与独立的 ARE 39 检查逐项证据、覆盖率。没有内部授权/治理信息时 NOT_VERIFIED，不给整个项目猜测一个 L4 级别，也不宣称 ARE 官方认证。
> 7. 分类写出正面观察、已复现可重现问题、设计优化建议、不确定现象和无法核实事项。公开高风险问题走私密披露而非社交平台公布利用细节。
> 8. 生成可脱敏、可复测的简短技术报告，包含时间、版本、输入、最小复现、来源/证据与影响。**不要自动在第三方 GitHub 仓库发 Issue、给维护者发邮件或把结果当作 ARE 本人背书。**
>
> 最终报告必须明确标记 **Independent community review / Not an ARE-issued certification**，并附上复现所需输入和已知证据边界。

公共第三方评估的价值是可重复的工程观察，而不是凭一次错误返回给开源项目打差评。
